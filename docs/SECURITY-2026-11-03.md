# Security review: 2026-11-03

Reviewed branch: main at bd6434bf2a8ae249df25beebdf95743017bd2630 (October 21).
No later main commits existed when this review started. This is a source review
and regression/build validation, not hardware penetration testing or a guarantee
that the complete boot chain is free of vulnerabilities.

## Version decision

Keep U-Boot v2026.10, upstream commit
5508406582f6f7120dce0c4b3059819a41788db2. The upstream release-cycle page lists
v2026.10 (October 5) as the current stable release; v2027.01-rc1 (October 26)
is development code. No stable version upgrade is required on November 3.

Keep the external TF-A Mbed TLS dependency at 3.6.7, the latest release listed
in the 3.6 LTS line. Mbed TLS 4.2.0 is a different API line and is not a drop-in
upgrade for this vendor TF-A. The vendor TF-A platform remains based on 2.10;
upstream 2.15 cannot replace its DDR, flash, eFuse and platform code without a
separate port and hardware qualification.

## Vendor TF-A findings and fixes

These interfaces are SiP secure-monitor calls originating in the non-secure
world. Exploitation requires an operating-system/bootloader context able to
issue those calls; this review has not established unauthenticated LAN reachability.
The memory-corruption findings are high priority because they cross into EL3.

| Finding in the reviewed baseline | Change |
| --- | --- |
| DM-key decryption copied an arbitrary caller length into 256-byte stack buffers, processed partial AES blocks, and always copied 256 output bytes. | Require 16-byte multiples from 16 through 256, check key retrieval and AES results, copy exactly the validated length, and erase temporary keys/plaintext. |
| GCM accepted an empty tag, merely logged oversized IV/tag lengths, and read a header before checking its size. | Snapshot and validate the complete header, require the format's full 16-byte tag, check IV/algorithm/flags, compare tags in constant time, and reject short input before reading it. |
| GCM ignored actual streaming output lengths and left plaintext after authentication failure. | Account for Mbed TLS 3.6 update/finish output, including partial blocks; erase output on backend/authentication failure. |
| PBKDF2 wrote an unchecked derived-key length into a fixed stack array. | Reject zero/oversized derived keys before derivation, preserve up to 128 bytes for SHA-256/SHA-512, use bounded string lengths and constant-time comparison, and erase derived keys. |
| Password SMC mappings omitted the second string/hash and discarded an unaligned input address. | Validate and map both complete fields plus the selected hash length, preserve the caller offset, and require NUL termination inside each field. |
| Crypto SMC pointer sums could wrap or target non-DRAM/secure memory; image decryption advertised a larger output capacity than it mapped. | Use 64-bit range checks against detected DRAM and EL3/optional OP-TEE exclusions before page rounding; limit loader output to the validated length; restore loader state and return errors without panicking. |
| Concurrent crypto calls shared loader state and settings. | Serialize crypto SMC dispatch and restore temporary mappings and FIP/hash state. |

Valid encryption format-1 images from tools/encrypt_fw, valid AES DM-key inputs,
and the documented password SMC layout retain their operations and SMC numbers.
The internal C password helper now receives explicit lengths. Malformed inputs
and zero/truncated authentication tags are deliberately rejected.

## Compatibility and remaining limits

Manual/physical Web Recovery, safe automatic recovery, serial and TFTP operations,
unsigned development builds and tag signing requirements remain unchanged.
No mandatory FIT signature enforcement or anti-rollback has been introduced.
Existing UBI firmware updates preserve the bootloader volumes as documented in
PERSISTENT-BOOT.md; arbitrary raw/whole-device writes cannot provide that guarantee.
XG-140G-TF and TF-S remain distinct experimental targets without hardware boot tests.

This patch does not make non-secure shared memory immutable. Its owner can alter
ciphertext/password data while a request runs, and can observe shared output.
Callers must not treat such buffers as trusted executable images without the
required signature verification. The GCM header and sensitive working values are
copied into secure storage; failure output is erased before returning.

Vendor eFuse programming, PHY/DDR calibration routines and prebuilt platform
objects require separate vendor/hardware review. Their privileged capabilities
are retained; this report does not certify their internal memory accesses or
prove the system safe against an already compromised kernel. Physical security,
ROM/eFuse signing policy and board-specific installation remain hardware concerns.

## Validation and deliverables

CI runs test/airoha/tfa_crypto_security.py against the actual modified C crypto
functions and extracted actual SMC handler definitions, using Mbed TLS 3.6 code.
ASan/UBSan cover crypto input/output; a separate UBSan run exercises fixed physical
address mappings and optional OP-TEE exclusion (those addresses overlap ASan's
host shadow space). Platform key retrieval, mappings and image-loader I/O are
stubbed only in the host harness. Full device builds compile the complete platform.

Cases include valid AES and password operations, output canaries, oversized keys,
short headers, zero/oversized tags, invalid algorithms/flags/IVs, valid and invalid
GCM messages of lengths 0, 1, 15, 16, 17, 255, 256, 257, 511, 512 and 513,
unterminated/unaligned password fields, wrapping ranges, secure/MMIO pointers,
map failures, loader output bounds and state restoration.

The existing recovery, UBI/persistence, CVE and compiled XG-140G identity checks
also remain in the 14-board build matrix. Consult the associated completed Actions
run for the actual pass/fail result; listing a check here is not a claim it passed.
No hardware flashing or boot test is performed by CI.

The source artifact includes ONUBL-2026-11-03.patch, a replacements ZIP preserving
repository-relative paths, individual replacement files, the complete source ZIP
and a SHA-256 manifest. The review patch is based on the main commit above and is
checked for reverse applicability before upload.
