# Security and dependency review — 2026-10-21

Reviewed the main source after the 2026-10-17 fixes and the two new experimental
XG-140G profiles. This is a targeted source and build review, not a claim that
all vulnerabilities have been eliminated or that the new hardware has booted.

## Versions and applicable advisories

U-Boot remains based on the official v2026.10 release, commit
5508406582f6f7120dce0c4b3059819a41788db2. Do not move vendor board support to an
unreleased development branch just to change the version number.
The previous [CVE review](SECURITY-2026-10-17.md) remains applicable:

- CVE-2026-71972 (BMP decoding) and CVE-2026-34878 (TF-A FIP bounds/read handling)
  retain their fixes and sanitizer regressions.
- The October 14 [USN-8930-1](https://ubuntu.com/security/notices/USN-8930-1)
  covers CVE-2026-74220/74221 (NFS), 74222 (lwIP wget lifetime), and 74225
  (DHCPv6 lengths). The v2026.10 base includes the relevant upstream fixes;
  no duplicate backport is added. Legacy NFS is not the recovery HTTP server.
- The [TF-A advisory index](https://tf-a.docs.trustedfirmware.org/en/latest/process/security.html)
  does not require enabling optional BL1 firmware update functionality or
  adding mitigations for cores absent from AN7581/AN7583. The FIP fix is retained.
- External TF-A crypto remains pinned and archive-hash checked at Mbed TLS
  3.6.7, the current 3.6 LTS release in the [official releases](https://github.com/Mbed-TLS/mbedtls/releases).
  Mbed TLS 4.2.0 is a separate major API line, not a drop-in upgrade for this
  TF-A fork. The version guard continues to reject older 3.6 releases.

No additional applicable public CVE requiring a new source backport was found
in the above sources in this review. U-Boot's separate vendored Mbed TLS copy
is not the external TF-A dependency; MBEDTLS_LIB is disabled in these board
builds. Enabling optional TLS or other currently disabled features requires a
fresh dependency/applicability review. Vendor binary DRAM components and the
running OpenWrt/ImmortalWrt kernel/packages are outside this source audit.

## Build-workflow improvements

Use full commit pins from official GitHub Actions releases:

- checkout 7.0.1: 3d3c42e5aac5ba805825da76410c181273ba90b1
- upload-artifact 7.0.2: cf430e030ddbb5b0abf93d22962f4752f3646cd9
- download-artifact 8.0.2: 9000827ccba6bdab643e8b6fd33ac0654aef8333

Checkout does not persist repository credentials. Bash's explicit workflow
shell enables pipefail so a failing build piped into tee cannot report success.
The private signing key is supplied only for tag builds; branch and PR builds
remain unsigned development builds. Tags still require AIROHA_REQUIRE_SIGNING=1
and fail closed without successful signing. Job permissions stay contents:read,
with contents:write restricted to the existing tag release job. Uploaded files
remain ZIP artifacts; the newer action's direct-upload mode is not enabled.
GitHub-hosted Ubuntu runners supply the required Node 24-capable runner.

## Recovery and persistence boundaries

Full manual/physical recovery, the serial console, TFTP, board-data handling and
privileged maintenance remain available. Automatic boot-failure recovery uses
boot_recovery_auto and httpd safe; only reset and boot-production task operations
are allowed. Uploads, downloads and privileged/unknown task operations receive
HTTP 403 in safe mode. The privilege state remains exposed by /api/info.
Privilege is held in running server state, not a user-editable environment flag.
The regression harness compiles the actual HTTP/parser/startup functions with
stubbed hardware to check this boundary and preserved manual behavior.

The new TF and TF-S targets inherit the same recovery and persistence code,
with separate board identities and output names. Hardware evidence and unknowns
are recorded in [XG-140G-TF.md](XG-140G-TF.md). Neither a matching CPU nor a passing
build establishes safe cross-flashing. FIT signature enforcement and anti-rollback
remain opt-in/future work; neither is made mandatory by this change.

CI runs existing UBI compatibility, persistent storage and FIP/BMP/crypto checks,
the HTTP security harness, syntax checks, all 14 builds, and compiled DTB/default
identity checks for both new boards. The source artifact contains individual
replacement files and ONUBL-2026-10-21.patch / ONUBL-2026-10-21-replacements.zip
against the pre-review main commit 82e2595b6d0f6e5343e066809f494e09bc114b40,
in addition to the existing complete v2026.10 source bundle and patch.
